# Implementation Plan: Professional Reports & Resale Value Export

This document outlines the strategy for implementing a professional PDF export feature in AutoCare, allowing users to generate verified maintenance reports for resale or record-keeping purposes.

## 1. Overview
The goal is to provide users with a "Verified Service History" document in PDF format. This document will aggregate all maintenance records, fuel logs, and expenses associated with a specific vehicle into a clean, printable, and shareable format.

## 2. Technology Stack
*   **PDF Generation:** Use the standard Android `android.graphics.pdf.PdfDocument` API for native, lightweight generation.
*   **Printing Framework:** Utilize `PrintHelper` or `WebView` (as a print adapter) for formatting complex layouts if necessary.
*   **File Sharing:** Use `FileProvider` to securely share the generated PDF with other apps (Email, WhatsApp, Google Drive).
*   **Data Source:** Room Database (Maintenance, FuelLoad, and Expense repositories).

## 3. Report Content & Structure
The report should be professionally branded and include:

*   **Header:**
    *   AutoCare Logo (Branding).
    *   Report Date.
    *   Vehicle Summary: Make, Model, Year, Plate, and Current Odometer.
*   **Section 1: Maintenance History (Primary):**
    *   Chronological table: Date, Service Type, Mileage, Cost, and Notes.
*   **Section 2: Operational Summary:**
    *   Total Fuel Consumption & Efficiency (Average Km/L).
    *   Total Cost of Ownership summary.
*   **Footer:**
    *   "Generated by AutoCare App".
    *   Page numbers.

## 4. Implementation Details

### Data Aggregation
*   Create a `ReportGenerator` class that takes a `VehicleId`.
    *   Fetches all related records from the database.
    *   Sorts records chronologically.
    *   Calculates summary statistics (Total spent, Total Km tracked).

### PDF Rendering
*   **Canvas Approach:** Use `PdfDocument.Page.getCanvas()` to draw text and tables directly. This offers high precision but requires manual layout math.
*   **HTML to PDF (Alternative):** Generate an HTML string representing the report and use `PrintAttributes` with a `WebView` to create the PDF. This is easier for complex styling and tables.

### Sharing Workflow
1.  User clicks "Export Service History" in the History Screen.
2.  App generates the PDF in the application's `cacheDir`.
3.  App generates a `content://` URI using `FileProvider`.
4.  Launch an `ACTION_SEND` intent with the PDF URI to allow the user to save or send the document.

## 5. User Experience (UX)
*   **Placement:** Add a "Share/Export" icon in the `HistoryScreen` TopBar.
*   **Customization:** Optional dialog to select date ranges (e.g., "Last 12 months" vs. "Full History").
*   **Visual Feedback:** Show a `CircularProgressIndicator` during generation, as building the PDF might take a few seconds for large histories.

## 6. Implementation Roadmap
1.  **Step 1:** Define the `FileProvider` in `AndroidManifest.xml` and `res/xml/file_paths.xml`.
2.  **Step 2:** Implement the `ReportGenerator` logic to fetch and format data.
3.  **Step 3:** Build the PDF rendering logic (UI to PDF).
4.  **Step 4:** Integrate the "Export" action into the `HistoryScreen` UI.
5.  **Step 5:** Add polishing (logo, styling, summary stats).
